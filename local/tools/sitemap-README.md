# Sitemap fors36

Текущий генератор — штатный `CSiteMap` модуля `search`, административная страница `/bitrix/admin/search_sitemap.php`. Он читает поисковый индекс. Восстановленная БД не содержит профилей генератора модуля `seo`. Сохраняем действующие адреса `/sitemap_index.xml` и `/sitemap_000.xml`; ссылка в `robots.txt` остаётся прежней.

## Постоянные исключения

Миграция `Version20261013112153` дополняет штатную настройку `search.exclude_mask`, включает обработчик `search.BeforeIndex` и удаляет старые технические поисковые записи через API `CSearch`. Содержимое страниц и инфоблоков не удаляется. Исключения действуют при повторной индексации и при генерации карты из административной панели либо существующего расписания.

Полный список находится в `local/php_interface/lib/SitemapPolicy.php`: макеты `/verstka/`, тесты, статистика, поиск, служебные разделы, `/text-page/`, фрагмент `/online-traning-main/`, старые разделы с редиректами, `/readme.html` и `/typography.php`. `/info/` уже имеет `noindex` в коде страницы. Обычные текстовые страницы, например `/oplata-gosposhliny/` и `/policy/`, сохраняются.

Макеты не подключают Битрикс, поэтому в начало соответствующих PHP-файлов добавлено подключение общего обработчика `local/php_interface/legacy_layout_redirect.php`. Он использует штатный `LocalRedirect` с кодом 301 и сохраняет параметры запроса. Это работает с Nginx и Apache. Прототипы деталок без связи с реальным элементом направляются на соответствующий список. `/verstka/discount*.php` ведут сразу на `/news/`, поскольку `/shares/` уже перенаправляется туда. Для `/verstka` Nginx может сначала добавить завершающий слеш своим редиректом.

Из `robots.txt` удалены только запреты для макетов с настроенными редиректами: поисковый робот должен иметь возможность получить 301. Запрет `/verstka/ui-kit.html` сохраняется.

## Выкладка task-ветки

1. До выкладки сохранить текущие `sitemap*.xml` и убедиться, что нет выполняющейся генерации или переиндексации. Проверить реальное расписание на сервере: локально профиль SEO, агент Sitemap и cron генерации не обнаружены. Не добавлять второй параллельный запуск.
2. Развернуть `bugfix/native-sitemap-seo` принятым для проекта способом. В `master` сливать после приёмки.
3. Из корня сайта применить только эту миграцию:

```sh
php bitrix/modules/sprint.migration/tools/migrate.php up Version20261013112153
```

4. Сгенерировать карту штатным генератором:

```sh
php local/tools/sitemap.php
```

CLI-обёртка принудительно использует HTTPS и блокирует одновременные запуски этой же обёртки. Она не блокирует независимый запуск из административной панели. Если требуется заменить команду в существующем cron, использовать этот скрипт из корня сайта, сохранив текущую периодичность. Сама задача не создаёт нового cron или агента.

5. Проверить XML-индекс и дочерние карты: нет исключённых путей, дублей и локального домена; `/contacts/` присутствует. Проверить 301 с `/verstka/contacts.php` на `/contacts/` и HTTP 200 на конечных страницах. Повторить генерацию и сравнить набор URL.

## Откат

До удаления файлов task-ветки выполнить:

```sh
php bitrix/modules/sprint.migration/tools/migrate.php down Version20261013112153
```

Миграция сохраняет прежние настройки и удаляемые поисковые записи в штатном хранилище Sprint Migration; `down()` восстанавливает их. После отката восстановить сохранённые перед выкладкой XML и вернуть предыдущую версию кода через обычный deploy-процесс. Для новой генерации со старыми настройками использовать штатную административную страницу: CLI-обёртка требует включённой политики исключений. Резервные данные остаются в БД, в Git их нет.
